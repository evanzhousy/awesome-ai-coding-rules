#### Bad — highlighted findings

> [!IMPORTANT]
> **CM-UX-034 · High · The shared symbol/Watchlist dialog never actually dismisses and traps the workstation**
>
> In the screenshot-free recovery tab, selecting the existing `AAPL` Watchlist row changed the dialog to `closed`, but the 896×648 dialog remained fully visible and its full-screen backdrop continued to receive pointer hits over the primary navigation at every poll from 2.1 through 31.1 seconds. The data underneath eventually became correctly AAPL-scoped, yet the trader could not click Rank or any other outside control. Pressing the dialog's own Close reproduced the same visible `closed` surface after 2.5 seconds. A reload was the only safe recovery. This turns the shared entry to ticker scope into a dead end on every core workstation. A greenfield modal must complete dismissal, remove its backdrop, return focus to the trigger, and leave the chosen transient scope usable. Acceptance signal: selecting a ticker, clicking Close, pressing Escape, or clicking the backdrop leaves zero visible dialog/backdrop nodes after the exit transition; primary navigation is immediately pointer/keyboard operable and a symbol-scope route-away/Back loop can complete without reload.

> [!IMPORTANT]
> **CM-UX-035 · High · Scope and Back transitions present stale or empty data as an authoritative result**
>
> At 2.1 seconds after selecting AAPL, the visible control had committed to `AAPL` and the live region announced `Filtering by AAPL`, but 99 of 100 rows were still unrelated symbols and no visible applying/loading guard prevented interpretation. A novice can reasonably read both intermediate states as settled market evidence. A greenfield workbench should keep scope, summaries, total, and rows atomic: either preserve the last-good set under an explicit `Applying AAPL…`/`Refreshing…` state, or block all evidence regions with one loading contract until the new result is authoritative. Acceptance signal: the scope label never names AAPL while non-AAPL rows remain actionable, and route return never renders `0 total records` unless an authoritative empty response has settled with an explanation and recovery path.

> [!IMPORTANT]
> **CM-UX-019 · Medium · The shared heart instruction still exposes an opaque save model**
>
> The shared desktop/mobile dialog repeats the Rank drawer label `HEART ADDS TO "CONSUMERED"`. It is technically specific, but a first-time user must infer that a heart means a durable save, that `consumered` is the currently targeted Watchlist, and that clicking the surrounding result instead performs a transient page filter. The same three-pane workspace also contains remove hearts, `New`, list actions, `Filter by this watchlist`, and auto-apply. A greenfield control would use direct verbs—`Filter current page by NVDA` and `Save NVDA to consumered`—and visually separate transient scope from durable collection management. Acceptance signal: every symbol row names both available consequences in plain language without teaching a heart metaphor or requiring the user to infer which Watchlist will persist the ticker.

> [!IMPORTANT]
> **CM-UX-036 · Medium · Mobile navigation and Watchlist controls are too small for safe scope management**
>
> At `390 × 844`, primary menu rows measured 36 pixels high and its Close target 32×32. The higher-risk Watchlist dialog was denser: adjacent list choices were only 26.6–30.4 pixels high, `New` was 38×22.8, ticker selection itself was a 260×19 text strip, remove buttons were 30.4×30.4, and dialog Close was 30.4×30.4. The page fits, but it achieves that fit by shrinking controls around persistent add/remove and scope-changing actions, increasing wrong-list and destructive mis-taps. A greenfield mobile design would use full-row interactive targets at least 44 pixels high, preserve spacing between select and remove, and move infrequent list management behind a clearly labeled secondary mode. Acceptance signal: every mobile nav, list, close, switch, add/remove, and scope action has an effective 44×44 minimum target with non-overlapping hit areas, while the dialog still fits and scrolls at 390 pixels.
